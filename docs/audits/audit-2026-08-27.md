### DIMENSION 2: ROUTING HEURISTIC QUALITY — 5/10

`smart_route()` uses regex keyword matching. False positives detected:
- `"code"` matches both coding and agentic — "json extraction code" hits coding first
- `"financial"` triggers high-effort routing before reaching financial OCR/vision paths

**Category coverage gaps:**
- No financial-domain routing beyond generic `financial analysis` regex
- No "summarize" / "translate" / "creative writing" category
- `classify_task()` and `smart_route()` have different regex patterns — classification/routing drift
- `routing_learner.py` records outcomes but never feeds back into routing decisions

### DIMENSION 3: COUNCIL ARCHITECTURE — 6/10

**Strengths:** 3-stage pipeline is sound, anonymized proposals (A/B/C), fast quorum mechanism, user interrupt support.

**Weaknesses:**
- Member selection falls back to picking any free model matching a keyword — not truly task-specialized
- Chairman selection regex diverges from `smart_route()` patterns
- Peer review is done by same council members — can identify own proposal with only 3 proposals
- No scoring calibration anchor (what's a 5 vs 8?)
- No council-lite mode for quick queries
- Paid chairman fallback bypasses `MAX_BUDGET`

### DIMENSION 4: FALLBACK CHAIN RESILIENCE — 4/10

**Weaknesses:**
